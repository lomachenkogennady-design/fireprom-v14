# ФАЙЕРПРОМ Metalworks

Единый портал: инженерный расчёт гибки/развёрток + коммерческие предложения,
общая база клиентов и история. Next.js 16 (App Router) · PostgreSQL · Drizzle ORM · Tailwind 4.

| Раздел | Путь | Что делает |
| --- | --- | --- |
| Панель | `/` | Статистика, лента операций, полный цикл |
| Технологу | `/bending` | K-фактор (DIN 6935), BA/BD/OSSB, V-матрица, усилие, 2D+3D превью, отверстия, DXF |
| Менеджеру | `/kp` | Тарифы лазер/плазма/ГАР, серийные скидки, зачёт остатка, НДС 22%, импорт DXF, печать |
| История | `/history` | Расчёты, КП и клиенты из PostgreSQL |

## ⚠️ Termux (Android / arm64): собирать только через Webpack

Next.js 16 по умолчанию собирает **Turbopack**, а под `android/arm64` для него
нет нативных биндингов — грузятся только WASM, и сборка падает:

```
Error: Turbopack is not supported on this platform (android/arm64)
```

Это **не ошибка кода** — `tsc --noEmit` проходит чисто. Нужен флаг `--webpack`.

### Быстрый старт на телефоне

```bash
cd ~/fireprom-next
npm install

bash scripts/termux.sh doctor   # проверка окружения
bash scripts/termux.sh db       # применить схему к БД
bash scripts/termux.sh dev      # → http://localhost:3000
```

Остальные команды:

```bash
bash scripts/termux.sh build    # прод-сборка (webpack)
bash scripts/termux.sh start    # прод-сервер
bash scripts/termux.sh check    # типы + сборка
```

Или напрямую, без обёртки:

```bash
npx next dev --webpack
npx next build --webpack
npx next start
```

> `npm run build` из `package.json` оставлен на Turbopack — так быстрее собирается
> на Vercel и на обычном Linux/x64. На Termux используйте `--webpack`.

### Если не хватает памяти

```bash
export NODE_OPTIONS=--max-old-space-size=2048
```

(скрипт `termux.sh` ставит это сам)

`next/font/google` скачивает Inter / JetBrains Mono / Unbounded во время сборки
и кладёт в `.next/cache`. Первая сборка — онлайн, дальше берётся из кеша.

## Регламент производства

`src/lib/shop.ts` — единый источник истины о том, что цех реально делает.
Главнее теоретических формул: прайс может содержать тариф на 12 мм, но если
лазер режет сталь до 5 мм, такую позицию нельзя ни посчитать, ни пообещать.

| Операция | Предел |
| --- | --- |
| Поле раскроя лазера | 2490 × 1240 мм (лист 2500 × 1250) |
| Резка: сталь, оцинковка | до 5 мм |
| Резка: нержавейка, алюминий | до 3 мм |
| Резка: цветные металлы | по запросу |
| Гибка, толщина | 0,2–2 мм штатно, толще по согласованию |
| Гибка, ширина | до 2490 мм |
| Гибка, глубина | 280 мм; 470 мм при ширине ≤ 2000 мм |
| Минимальная полка | 11 мм |
| Минимальный внутренний размер | 12 мм |
| Радиус гиба | R = t |

Проверка встроена в оба модуля: в расчёте гибки блоком «Регламент
производства», в КП — построчными замечаниями и баннером, который прямо
говорит, что такое КП отправлять нельзя. Толщины в выпадающих списках
ограничены возможностями резки по каждому материалу.

### R = t против воздушной гибки

Регламентный радиус (R = t) и радиус воздушной гибки на V12 (≈1,9 мм независимо
от толщины) — разные вещи. Они сходятся около t = 2 мм и расходятся на тонком
металле:

| s, мм | R воздух | R = t | Δ развёртки |
| --- | --- | --- | --- |
| 0,5 | 1,9 | 0,6 | 4,30 мм |
| 1,0 | 1,9 | 1,0 | 2,96 мм |
| 1,5 | 1,9 | 1,5 | 1,32 мм |
| 2,0 | 1,9 | 2,0 | −0,44 мм |

Четыре миллиметра на детали в 167 мм — это брак. Поэтому в калькуляторе режим
переключается явно, а при существенном расхождении выводится предупреждение с
фактической разницей. R = t на тонком металле достижим калибровкой или узким
ручьём — режим надо согласовать с наладчиком.

## Раскрой на листе (nesting)

Модуль КП считает не «массу × 1.25», а фактический раскрой: сколько листов
уйдёт, как детали лягут, что останется.

- Форматы листа ограничены полем реза 2490 × 1240: листы 1500 × 3000 и длиннее
  физически не режутся и в списке отсутствуют.
- Алгоритм — полочный FFDH с поворотом на 90°, группировка по паре
  «материал + толщина» (нельзя нестить 2 мм нержавейку с 3 мм сталью).
- Учитывается ширина реза: лазер 0.2–0.5 мм, плазма до 3.5 мм,
  гидроабразив по толщине; плюс зазор между деталями и отступ от кромки 10 мм.
- **Автоподбор формата** ранжирует листы по стоимости металла за вычетом
  делового остатка, а не по числу листов: два листа 1500×6000 (18 м²) дороже
  трёх листов 1500×3000 (13.5 м²).
- Деловой остаток выделяется, если полоса ≥ 150 мм и ≥ 0.12 м² — он
  возвращается на склад или зачитывается клиенту по цене лома.
- Карта листа рисуется на SVG, темозависимо, с подписями и пометкой
  повёрнутых деталей (↻).

Ключевая цифра — разница между раскроем и старой оценкой ×1.25: она прямо
показывает, сколько КП недосчитывает или переоценивает.

## Jarvis — встроенный технолог

Плавающий ассистент в правом нижнем углу. Отличие от обычного чат-бота:
он **видит состояние вашего экрана** и отвечает по фактическим числам расчёта.

Архитектура двухслойная:

| Слой | Когда работает | Что отвечает |
| --- | --- | --- |
| **Инженерный движок** (`src/lib/jarvis/expert.ts`) | всегда, ключи не нужны | минимальная полка, K-фактор, матрица V, усилие, развёртка, BA/BD, масса, пружинение, цена, порядок гибов, проверка технологичности |
| **Языковая модель** | если задан ключ в окружении | свободные формулировки; получает те же числа в системном промпте |

Числа принципиально считаются кодом, а не моделью: на вопрос «какая минимальная
полка» LLM выдумала бы правдоподобное значение, а движок берёт фактические
V и толщину из калькулятора. В ленте у каждого ответа стоит метка источника —
`расчёт` или `модель`.

### Как контекст попадает в Jarvis

```
bending-calculator ──usePublishSnapshot()──┐
                                            ├─→ JarvisProvider (React Context)
quote-builder ─────usePublishSnapshot()────┘         │
                                                      └─→ POST /api/jarvis
```

Снимок содержит материал, толщину, полки, углы гибов, отверстия и весь результат
расчёта (или позиции КП с раскладкой себестоимости).

### Подключить языковую модель (необязательно)

Добавьте в переменные окружения любой из ключей — провайдер определится сам:

```bash
OPENAI_API_KEY=sk-...          # или
OPENROUTER_API_KEY=sk-or-...   # или
DEEPSEEK_API_KEY=...           # или
GROQ_API_KEY=gsk_...

# необязательно:
LLM_MODEL=gpt-4o-mini
LLM_BASE_URL=https://...       # для self-hosted / прокси
```

Ключ читается только на сервере в `/api/jarvis` и в браузер не попадает.
Без ключа ассистент полностью функционален — недоступны лишь свободные
формулировки вне инженерной базы.

## База данных

Схема — `src/db/schema.ts` (4 таблицы: `clients`, `bending_calculations`,
`quotes`, `quote_items`). Миграции не нужны, схема накатывается напрямую:

```bash
npx drizzle-kit push
```

Строка подключения — `DATABASE_URL` в `.env` (шаблон — `.env.example`).
SSL включается автоматически для любого не-локального хоста, так что Supabase,
Neon и RDS работают без правок кода.

### Сборка не требует БД

Подключение создаётся **лениво** — при первом обращении к `db`, а не при импорте
модуля. Поэтому `next build` проходит на машине без PostgreSQL (Termux, CI,
Vercel до настройки переменных).

Без `DATABASE_URL` приложение запускается и все страницы открываются; расчёты
гибки и КП считаются локально в браузере. Не работает только сохранение:

| Endpoint | Ответ без БД |
| --- | --- |
| `/api/health` | `503 {"ok":false,"db":"unconfigured","hint":...}` |
| остальные API | `503 {"error":"База данных не настроена","hint":...}` |

Если `DATABASE_URL` задан, но сервер недоступен — код `500` и `"db":"error"`
с текстом от драйвера.

### Локальный PostgreSQL в Termux

```bash
pkg install postgresql
mkdir -p $PREFIX/var/lib/postgresql
initdb $PREFIX/var/lib/postgresql
pg_ctl -D $PREFIX/var/lib/postgresql -l $PREFIX/var/log/postgresql.log start
createdb app_db

echo "DATABASE_URL=postgresql://$(whoami)@127.0.0.1:5432/app_db" > .env
bash scripts/termux.sh db      # накатить схему
bash scripts/termux.sh start   # запустить портал
```

Проверка: `curl localhost:3000/api/health` → `{"ok":true,"db":"connected"}`.
После перезагрузки телефона Postgres нужно поднимать заново тем же `pg_ctl ... start`.

## Деплой (российские площадки, без VPN)

Проект упакован в Docker и собирается в режиме `output: "standalone"`:
Next трассирует только нужные модули, поэтому в образ едет **55 МБ** вместо
756 МБ `node_modules`. Это то, что позволяет приложению жить на бесплатных
тарифах с 0.5 ГБ RAM.

Схема БД накатывается сама при старте контейнера — `scripts/init-db.mjs`
выполняет идемпотентный SQL (`CREATE TABLE IF NOT EXISTS`, имена ограничений
совпадают с drizzle-kit). `drizzle-kit` в production-образе не нужен.

| Площадка | Как деплоить | Нюанс |
| --- | --- | --- |
| **Amvera** | git push → читает `amvera.yml` → собирает `Dockerfile` | Managed PostgreSQL в той же панели |
| **ONREZA** | подключить репозиторий, Docker | 60 мин сборки/мес — собирайте образ локально |
| **RelaxDev** | Docker / Node | 2 ГБ RAM — хватает и на сборку |
| **dockerhosting.ru** | `docker compose up -d` | БД нет → поднимается из `docker-compose.yml` |
| любой VPS | `docker compose up -d --build` | полный контроль |

### Amvera (рекомендуется: хостинг + БД в одном месте)

1. Создать приложение → тип **Docker** (конфиг `amvera.yml` уже в репозитории).
2. Создать сервис **PostgreSQL**, скопировать строку подключения.
3. В разделе **Переменные** задать:
   ```
   DATABASE_URL = postgres://<user>:<pass>@<имя-сервиса-БД>:5432/<db>
   ```
4. `git push amvera master` — платформа соберёт образ и запустит контейнер.
5. Проверить: `https://<ваш-домен>/api/health` → `{"ok":true,"db":"connected"}`.

Схема создастся автоматически при первом старте — заходить в БД руками не нужно.

### VPS / dockerhosting.ru — полный стек одной командой

```bash
git clone <репозиторий> && cd fireprom-metalworks
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)" > .env
docker compose up -d --build
docker compose logs -f app
```

Поднимутся два контейнера: `app` (портал на :3000) и `db` (PostgreSQL с томом
`pgdata`). Порт БД наружу не публикуется — доступ только изнутри compose-сети.

### Если на площадке мало памяти для сборки

Сборка тяжелее рантайма. Вариант — собрать образ у себя и залить готовый:

```bash
docker build -t fireprom:latest .
docker save fireprom:latest | gzip > fireprom.tar.gz   # → загрузить на сервер
```

### Что нужно знать про сборку

- **Интернет обязателен**: `next/font/google` скачивает Inter / JetBrains Mono /
  Unbounded на этапе сборки.
- **`DATABASE_URL` при сборке не нужен** — подключение ленивое.
- Порт задаётся переменной `PORT` (по умолчанию 3000), слушаем `0.0.0.0`.

## Инженерные допущения

- **K-фактор** — таблица DIN 6935 по R/t (0.28 … 0.5)
- **BA** = θ·(R + K·T), **OSSB** = (R+T)·tan(θ/2), **BD** = 2·OSSB − BA
- **V-матрица** = 6…10·T по материалу, **R** ≈ 0.16·V (воздушная гибка)
- **Усилие** ≈ 650·T²/V кН/м × коэффициент материала
- **Мин. полка** = 0.7·V — короче деталь проваливается в матрицу
- **DXF**: слои `CUT` (контур), `BEND` (пунктир + угол/направление),
  `HOLES` (окружности + разметка центров), `TEXT`
