# Сессия 27.09.2026 — Мобильный доступ через NetBird

## Цель
Настроить доступ к порталу FireProM не только через Wi-Fi офиса, но и через мобильный интернет.

## Проблема
- Провайдер даёт **CGNAT** (серый IP)
- Проброс портов через роутер Cudy — **невозможен**
- Иностранные туннели (Cloudflare, Localhost.run, Pinggy, TunnelHunt) — **блокируются в РФ**

## Решение: NetBird P2P VPN

NetBird — это mesh-VPN на WireGuard, работает за CGNAT, не блокируется в РФ.

### Установка
- **APK:** github.com/netbirdio/android-client/releases (v0.6.1)
- **Регистрация:** app.netbird.io (бесплатно до 100 устройств)
- **Аккаунт:** lomachenkogennady@gmail.com

### NetBird IP (записаны в `~/netbird-ips.txt`)
- **Samsung:** 100.96.139.87
- **Doogee:**  100.96.47.95

### Проверка
| Тест | Результат |
|---|---|
| Ping Samsung ↔ Doogee | 0% потерь (40–345 мс) |
| Ollama через NetBird | 200 |
| SSH через NetBird | ok |
| Jarvis expert | 0.078 сек |
| Jarvis LLM (Ollama) | 29 сек |

### Конфигурация
- `.env` → `OLLAMA_URL=http://100.96.47.95:11434`
- `.env` НЕ коммитится в Git (в `.gitignore`)
- NetBird включён **постоянно на Doogee**, на Samsung — **по необходимости**

## Конфликт VPN
NetBird конфликтует с другими VPN на Android (система поддерживает только один).
- **Doogee** — NetBird всегда, DeepSeek не нужен
- **Samsung** — обычный VPN для DeepSeek, NetBird включать на время тестов

## Уроки
1. **CGNAT + РФ = NetBird.** Единственное бесплатное и рабочее решение.
2. Иностранные туннели в РФ — тупик. Не тратить время повторно.
3. На Android — **только один VPN одновременно**. Планировать переключения.

## Дополнение: Безопасность FireProM API (Doogee)

### Проблема
Flask-сервер `~/fireprom/server/api.py` на Doogee имел `/exec` без аутентификации и с `shell=True`.
Через NetBird это давало root-доступ любому в сети.

### Решение
Переписан `api.py`:

| Что | Было | Стало |
|---|---|---|
| Аутентификация | Нет | X-API-Key (401 без ключа) |
| /exec | shell=True | shell=False + shlex + белый список |
| Path traversal | Уязвим | os.path.basename() |
| Порт | 5000 (хардкод) | 5001 (из .env API_PORT) |
| Автозапуск | Ручной | ~/.termux/boot/04-fireprom-api.sh |

### Белый список команд
ls, cat, head, tail, wc, df, du, free, uptime, date, whoami, ps, pgrep, systemctl, ollama

### Проверка
- Без ключа → 401
- С ключом → 200
- rm -rf / → 403 command not allowed
- uptime → 200

### Адреса
- Wi-Fi:   http://192.168.10.21:5001
- NetBird: http://100.96.47.95:5001

## Дополнение: Мобильный доступ к порталу через NetBird — РАБОТАЕТ

### Проблема
После ребута Samsung портал :3000 отвечал 000 через NetBird-IP.
Причины: (1) Postgres не поднялся, (2) Next.js не запущен,
(3) тумблер NetBird в APK был выключен.

### Диагностика
- `pg_ctl status` → no server running
- `ps aux | grep next` → пусто
- Скриншот NetBird → «Отключено»

### Решение
1. Postgres: `pg_ctl -D $PREFIX/var/lib/postgresql -l ~/postgres.log start`
2. Next.js: `nohup npx next dev --webpack -H 0.0.0.0 > ~/next-dev.log 2>&1 &`
3. NetBird: включить тумблер в APK → «Подключено»

### Результат
| Адрес | Код |
|---|---|
| http://192.168.10.44:3000 (Wi-Fi) | 200 |
| http://100.96.139.87:3000 (NetBird) | 200 |
| http://100.96.47.95:5001 (Doogee API) | 200 |

### Замечания
- `127.0.0.1:3000` → 000 из-за резолва localhost в IPv6 (::1);
  Next.js слушает IPv4. Для браузера на самом Samsung не проблема.
- Boot-скрипт `15-fireprom.sh` обновлён: pkill + `-H 0.0.0.0`.
- `02-ollama.sh` убран в `~/.termux/boot/archive/` — Ollama на Doogee.

### Итог
NetBird заменяет туннели (Cloudflare/Pinggy) для доступа сотрудников
с мобильного интернета. VPS+frp — для публичной ссылки клиентам
(без установки NetBird).

## Дополнение: Миграция портала FireProM v14 Samsung → Doogee

### Причина миграции
Samsung: слабый CPU/диск (97%, 3.8G free), не тянет Next.js + Postgres + Ollama.
Doogee: 466G диск (212G free), свободная RAM, уже держит Ollama и FireProM API.

### Целевая архитектура
- **Samsung** — пульт управления: терминал + SSH-клиент. Только `01-ssh.sh` в boot.
- **Doogee** — сервер: Next.js :3000 + Postgres 18.6 + Ollama :11434 + FireProM API :5001
- **Внешний доступ** — NetBird: `http://100.96.47.95:3000`
- **Офисный доступ** — Wi-Fi: `http://192.168.10.21:3000`

### Что перенесено
| Компонент | Samsung (было) | Doogee (стало) |
|---|---|---|
| Исходники `~/fireprom-v14` | 726M | 2.2M (без node_modules, .next) |
| node_modules | 494M | 461M (переустановлены через npm install) |
| Postgres data | 64M | восстановлено из pg_dump |
| Ollama | ❌ нет | ✅ 6 моделей (переиспользована) |
| FireProM API `:5001` | ❌ нет | ✅ (был раньше) |

### Ключевые шаги
1. Установлены на Doogee: `nodejs-lts 24.18.0`, `postgresql 18.6`, `rsync 3.5.1`
2. Дамп Samsung: `pg_dump --no-owner --no-privileges -Fc` → 24K custom-format
3. Перенос кода: `tar+ssh` (без node_modules, .next, *.bak)
4. `initdb` на Doogee в `$PREFIX/var/lib/postgresql`
5. `pg_restore --no-owner --no-privileges --no-acl` в новую БД `app_db`
6. `npm install` — 394 пакета за 51 секунду (npm registry без проблем)
7. Одобрены `install-scripts` для `esbuild@0.25.12`, `sharp`, `unrs-resolver`
8. Правка `.env`: `DATABASE_URL` юзер `u0_a624` → `u0_a304`, `OLLAMA_URL` → `127.0.0.1:11434`
